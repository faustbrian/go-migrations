package migrations // import "github.com/faustbrian/go-migrations/v5"

Package migrations loads immutable SQL histories, validates checksum-bound
ledger state, and coordinates plans, execution, baselines and dirty recovery.
Construct a Source and Backend, then use NewRunner for database operations;
PlanUp, PlanDown and BuildStatus are database-independent validation helpers.

Each runner operation loads source before acquiring a backend session and
validates that loaded history against the locked ledger. Callers must keep
deployment sources immutable; the database lock does not freeze a filesystem.
The runner borrows its dependencies, starts no goroutines and does not close
the caller's database. Shared sources, backends and observers must support the
concurrency with which callers invoke them.

SQL is trusted deployment code, not a sandboxed or authorized request.
A checksum detects identity changes; it is neither a signature nor proof that
SQL is safe or reversible. Recovery records an operator-reviewed assertion,
not an automatic inspection or repair of database effects. See the owned v1
format in docs/migration-format.md and lifecycle in docs/operations.md.

type Backend interface {
	// Acquire returns a nonnil exclusively owned session or an error. The
	// backend must serialize cooperating jobs, honor cancellation and ensure an
	// unsuccessful acquisition does not leave an unmanaged locked connection.
	Acquire(context.Context) (Session, error)
}
    Backend is the replaceable migration-engine conformance boundary.

    Session.Apply must return only after both execution and owned-ledger
    persistence have reached an explicit recoverable outcome. Implementations
    must leave a dirty record when non-transactional execution has an uncertain
    or partial result. Every operation must honor its context and return bounded
    results required by Session.

type Checksum struct {
	// Has unexported fields.
}
    Checksum is a SHA-256 digest used for migration identity or a
    package-defined schema fingerprint. Its zero value is invalid for persisted
    contracts.

func ChecksumData(canonical []byte) Checksum
    ChecksumData hashes the supplied bytes with SHA-256 without normalization,
    validation or authentication. Callers define any canonical framing;
    migration identity instead uses the built-in versioned, byte-length-prefixed
    format.

func ParseChecksum(value string) (Checksum, error)
    ParseChecksum accepts exactly sha256: followed by 64 lowercase hexadecimal
    digits, rejecting the all-zero digest. Other spellings are not normalized.

func (checksum Checksum) GoString() string
    GoString prevents checksum internals from becoming an accidental public
    serialization contract while keeping diagnostics useful.

func (checksum Checksum) String() string
    String returns the algorithm-qualified ledger representation.

	// Has unexported fields.

type FSSource struct {
	// Has unexported fields.
}
    FSSource loads canonical SQL migrations from one cancellation-aware source
    directory and rejects unrelated entries so packaging mistakes fail closed.
    It borrows the provider and does not freeze directory/file reads into
    an atomic snapshot. Use immutable deployment artifacts, not a changing
    directory.

func NewFSSource(sourceFS SourceFileSystem, root string, options ...FSSourceOption) (*FSSource, error)
    NewFSSource constructs a source rooted at a valid fs.ValidPath directory of
    at most MaxMigrationSourceRootBytes. It borrows sourceFS without invoking
    it itself; caller options run left-to-right until the first nil or failing
    option.

func (source *FSSource) Load(ctx context.Context) ([]Migration, error)
    Load reads, validates and sorts the complete migration history using a
    finite load context and inclusive provider budgets. It returns no partial
    history on error. Filename versions may have leading zeroes; their numeric
    identities must be unique. SQL file directives use the owned v1 format,
    not SQL grammar. Provider errors are reduced to context/budget/encoding
    classifications or ErrInvalidSource; this does not sanitize arbitrary custom
    Source errors.

type FSSourceOption func(*FSSource) error
    FSSourceOption configures a filesystem source during construction only.

func WithSourceTimeout(timeout time.Duration) FSSourceOption
    WithSourceTimeout replaces the ten-minute complete-load timeout with a
    positive duration. This bounds cooperative provider work, not arbitrary
    code.

type Migration struct {
	// Has unexported fields.
}
    Migration is an immutable canonical SQL migration.

    Fields are intentionally private so callers and execution engines cannot
    mutate identity or persisted checksum state after validation.

func NewMigration(
	version Version,
	name string,
	transactionMode TransactionMode,
	upSQL string,
	downSQL string,
) (Migration, error)
    NewMigration validates identity, transaction mode and UTF-8, NUL-free SQL
    totaling at most 16 MiB. Names contain lowercase ASCII letters/digits with
    single separating underscores and at most MaxMigrationNameBytes bytes.
    Up SQL must not be blank; empty down SQL denotes irreversibility, whereas
    nonempty whitespace-only down SQL is rejected. SQL bytes and line endings
    are preserved, not parsed for grammar or normalized before the v1 checksum.
    Unlike FSSource file validation, this constructor does not reject a BOM.

func (migration Migration) Checksum() Checksum
    Checksum returns the immutable content digest.

func (migration Migration) DownSQL() string
    DownSQL returns the canonical rollback SQL, or an empty string when the
    migration is irreversible.

func (migration Migration) Name() string
    Name returns the canonical migration name without version or extension.

func (migration Migration) TransactionMode() TransactionMode
    TransactionMode returns the execution transaction policy.

func (migration Migration) UpSQL() string
    UpSQL returns the exact validated forward SQL, including whitespace.

func (migration Migration) Version() Version
    Version returns the immutable migration version.

type Plan struct {
	// Has unexported fields.
}
    Plan is a deterministic execution plan derived from source and ledger state.

func PlanDown(available []Migration, records []Record, count uint64) (Plan, error)
    PlanDown validates the complete persisted history and returns exactly count
    rollback steps in descending version order. Count must be positive and fit
    the applied history; every selected migration must have down SQL. It never
    crosses a baseline or proves that down SQL restores the original schema.

func PlanUp(available []Migration, records []Record) (Plan, error)
    PlanUp validates the complete persisted history and returns pending
    migrations in ascending version order. Any ambiguity fails closed. Inputs
    must be strictly ordered, within MaxMigrationFiles/MaxMigrationRecords and
    form an unchanged clean source prefix above any baseline. It performs no I/O
    and does not retain the caller's slices.

func (plan Plan) Steps() []Step
    Steps returns a copy so callers cannot mutate a validated plan.

type Result struct {
	// Has unexported fields.
}
    Result describes the successful acknowledged prefix of one runner Up/Down
    invocation, including on error. It is not a whole-batch transaction receipt:
    the failing step or cleanup may also have changed durable database state.

func (result Result) Records() []Record
    Records returns a copy of acknowledged records in execution order. Down
    returns the historical clean records that were removed, not surviving rows.

type Runner struct {
	// Has unexported fields.
}
    Runner coordinates source validation, exclusive locking, history
    revalidation, planning, and backend execution.

func NewRunner(source Source, backend Backend, options ...Option) (*Runner, error)
    NewRunner borrows source/backend without loading or acquiring them itself.
    Options are caller code. It rejects nil interfaces/options, applies options
    left-to-right until failure and starts no goroutines. Typed-nil dependencies
    and arbitrary callback/backend panics are not generally validated or
    contained. Operations require a nonnil context and usable dependencies.

func (runner *Runner) Baseline(ctx context.Context, baseline Baseline) (record Record, err error)
    Baseline validates and records an existing schema without replaying any
    historical framework migrations. The owned ledger must be empty, and every
    Go-owned source migration must have a version strictly above the baseline.
    The session must implement Baseline(context.Context, Baseline) (Record,
    error), otherwise ErrBaselineUnsupported is returned. PostgreSQL compares
    its selected catalog fingerprint transactionally; matching it does not
    verify every schema or security property. Cleanup errors can follow a
    committed baseline.

func (runner *Runner) Down(ctx context.Context, count uint64) (result Result, err error)
    Down plans exactly count clean applied migrations, newest first, validating
    loaded source against locked ledger history. Count must be positive;
    planning fails before SQL if any selected migration is irreversible or
    crosses a baseline. Execution can stop partway: Result contains acknowledged
    removals, and an error does not establish that the failing step made no
    durable change.

func (runner *Runner) Plan(ctx context.Context) (plan Plan, err error)
    Plan loads source before locking and validates that history against the
    locked ledger without executing migration SQL. It can initialize the ledger;
    it is not an I/O-free operation or a reservation for a later Up call.

func (runner *Runner) Recover(
	ctx context.Context,
	recovery Recovery,
) (result RecoveryResult, err error)
    Recover resolves one checksum-matched dirty migration after the operator
    has verified that its effects are either fully applied or fully removed.
    The session must support the Recover method taking context.Context,
    Migration and RecoveryAction and returning (Record, error), otherwise
    ErrRecoveryUnsupported is returned. The runner checks source and
    dirty-record identity but does not execute SQL or verify the asserted
    effects. A release error can follow a persisted recovery decision.

func (runner *Runner) Status(ctx context.Context) (status Status, err error)
    Status loads source before locking, prepares/reads the ledger under the
    session lock and returns their validated status. It does not inspect live
    SQL effects or freeze source changes; ledger preparation may execute SQL.

func (runner *Runner) Up(ctx context.Context) (result Result, err error)
    Up loads source, acquires a session and validates that loaded history
    against the locked ledger before applying pending steps in ascending order.
    The lock coordinates backend jobs, not source mutations or unrelated
    database writers. Each step has its own backend transaction policy, not a
    batch transaction. On failure Result contains only earlier acknowledged
    steps; inspect database and ledger state before retry because the failing
    step or cleanup may have followed durable changes. The runner does not retry
    automatically.

type Session interface {
	// Prepare initializes the owned ledger on the lock-owning connection. It
	// may execute SQL even for a plan/status operation.
	Prepare(context.Context) error
	// Records returns the complete, version-ordered ledger within
	// MaxMigrationRecords, with returned data stable for the caller to validate.
	Records(context.Context) ([]Record, error)
	// Apply executes up SQL and persists its matching clean record on success.
	// Transactional SQL and ledger writes must be atomic; nontransactional work
	// must persist dirty state before executing SQL. Errors can follow durable
	// changes and must not be interpreted as proof that nothing ran.
	Apply(context.Context, Migration) (Record, error)
	// Rollback executes down SQL and removes the matching record on success,
	// returning the removed clean record. It has the same transactional and
	// explicit dirty-outcome obligations as Apply.
	Rollback(context.Context, Migration) (Record, error)
	// Release relinquishes the session's connection and exclusive ownership.
	// Runner attempts it once after acquisition using a detached finite context;
	// cleanup errors are joined with any operation error.
	Release(context.Context) error
}
    Session represents exclusive migration-job ownership bound to one physical
    database connection. Ledger preparation, reads, and execution all happen
    through this value so connection loss and lock loss cannot be separated from
    execution and a one-connection pool cannot deadlock during preparation.
    Records must return at most MaxMigrationRecords entries.

type Source interface {
	// Load returns a complete history or an error, not a usable partial history.
	// It runs before the runner acquires the database lock.
	Load(context.Context) ([]Migration, error)
}
    Source loads a complete immutable migration history. Implementations must
    honor the supplied context, return at most MaxMigrationFiles entries in
    strictly increasing version order, and keep returned data stable during use.
    Runner retains source errors without removing their causes; custom sources
    must keep their own diagnostics safe.

	// Directory reports whether the entry is a directory.

    SourceEntry is the bounded directory metadata needed to discover a

type SourceFileSystem interface {
	// ReadDir returns the complete directory inventory, including unrelated
	// entries for FSSource to reject. It must bound metadata before retention.
	ReadDir(ctx context.Context, root string, limits SourceDirectoryLimits) ([]SourceEntry, error)

    error for other failures; FSSource redacts those private errors as
    ErrInvalidSource.

package migrationsservice // import "github.com/faustbrian/go-migrations/v5/adapters/service"

Package migrationsservice adapts an explicit migrations.Runner to the standard
Service v3 migrate command.

The adapter owns no database or migration semantics. Callers load
their configuration, construct the runner and resource components,
and select the runner operation. The adapter fixes only the command name,
one-shot role, task boundary, and cleanup ordering required by service.
Callbacks run under service contexts and retain their errors; the adapter does
not contain their panics or provide a new authorization/redaction boundary.
See TestCommandPreservesOneShotOrderingAndCallerOwnership in service_test.go.

package conformance // import "github.com/faustbrian/go-migrations/v5/conformance"

Package conformance provides the reusable behavioral test suite every
migration backend must pass without depending on its execution engine. Run uses
caller-provided isolated databases and SQL; it creates no database itself. The

security or supported-database qualification. Backend owners retain those

package postgres // import "github.com/faustbrian/go-migrations/v5/postgres"

Package postgres implements the public.migrations ledger and connection-bound
advisory-lock backend for migrations.Runner. New borrows a caller-owned
*pgxpool.Pool; it does not open, close or migrate the database at construction.
Acquire owns one leased connection until Release. Cooperating jobs in the same
database share a stable lock; unrelated schema writers are not excluded.

Transactional SQL and ledger changes use one transaction per migration.
Nontransactional execution persists dirty state first; unresolved dirty
outcomes require explicit operator review/recovery. An error during commit or
timeout cleanup can follow durable changes; inspect state before retrying.
Finite contexts bound work; rollback and connection close use detached finite
deadlines.

Default PostgreSQL operation formatting hides driver diagnostics, but error
traversal may expose the original cause. Schema inspection returns sensitive
definitions and covers only selected catalog properties, not a security audit.
See docs/operations.md and docs/threat-model.md (risks 003, 006 and 007).

TYPES

type Backend struct {
	// Has unexported fields.
}
    Backend owns PostgreSQL preparation and creates connection-bound sessions.

func New(pool *pgxpool.Pool, options ...Option) (*Backend, error)
    New constructs the backend without using pool itself or taking its
    ownership. Caller options run left-to-right until a nil/failing option;
    repeated settings use the last value. Defaults are 30-second acquisition,
    five-minute statement and ten-minute primary-operation timeouts. Each
    session leases one pool connection for its lifetime, so size the pool for
    concurrent sessions plus inspection and discovery. The caller closes the
    pool after all sessions finish and must not mutate options during use.

func (backend *Backend) Acquire(ctx context.Context) (migrations.Session, error)
    Acquire waits for the stable package advisory lock on one physical
    connection and returns all subsequent session operations bound to it. Its
    lock timeout includes pool acquisition and polling. Database failures are
    not retried; uncertain lock-query failures discard the physical connection.
    A successful caller must Release the session even after operation failure.

func (b *Backend) AcquireCommand(ctx context.Context) (*CommandSession, error)
    AcquireCommand acquires native ownership without preparing any schema.
    It preserves existing Runner and Session contracts and their global lock.

func (backend *Backend) ForNamespace(namespace string) (*Backend, error)
    ForNamespace derives an IO-free backend for one independent migration owner.
    It borrows the same pool and copies timeout policy without changing the
    receiver. Namespace is canonical lowercase ASCII snake case, starts with a
    letter, and contains 1..46 bytes. Empty, uppercase, ambiguous or oversized
    names return ErrInvalidConfig; values are never normalized or truncated.

    The exact ledger is public.golib_migrations_<namespace>. No other history is
    discovered, adopted, renamed or merged. Retain the same namespace throughout
    an owner's lifetime; changing it selects empty/different authority, not
    an upgrade. Selection does not alter migration SQL, versions or checksums
    and is not an authorization boundary. The default backend still owns
    public.migrations.

    Every operation, including inspection/baseline and atomic installation,
    uses the selected ledger. Schema inspection remains database-wide:
    only this ledger's objects are excluded; nonselected ledgers remain visible.
    All owners retain the same native advisory lock so schema mutation stays
    serialized. Derived backends are safe for concurrent use with immutable
    configuration; the caller retains pool ownership. Nil/zero receivers deny
    without IO.

func (backend *Backend) Inspect(ctx context.Context) (migrations.Checksum, error)
    Inspect returns a fingerprint of the package-selected catalog query using
    a separate leased connection, without taking the migration advisory lock or
    changing the ledger. It does not freeze concurrent DDL for a later Baseline.

func (backend *Backend) InspectObjects(ctx context.Context) ([]SchemaObject, error)
    InspectObjects returns selected catalog identities/definitions for review,
    excluding the package-owned ledger. The caller owns the returned slice; text
    can contain sensitive SQL/literals and should not enter routine diagnostics.
    It does not take the advisory lock. The query includes relations, columns,
    constraints, indexes, triggers, selected policy expressions, enum/domain
    types, functions and extension versions, but not role grants/ownership,
    policy role targets, RLS enabled/forced flags, row contents or all
    PostgreSQL properties. A matching fingerprint therefore does not certify
    the whole schema/security state; review those omitted properties separately
    before adoption.

func (backend *Backend) InstallFresh(ctx context.Context, history []migrations.Migration, preflightSQL string) (records []migrations.Record, err error)
    InstallFresh installs a complete ordered history and optional package-owned
    preflight SQL in one transaction, retaining each original version/checksum.
    Ledger creation, preflight effects and every migration roll back together
    on execution failure. Existing nonempty history returns ErrLedgerConflict
    before preflight execution; this is not an upgrade, baseline or automatic
    retry API.

    Only reviewed transactional SQL is accepted: preflight and migration SQL
    must not contain transaction-control statements or nontransactional effects.
    Empty histories, invalid ordering, no-transaction steps and combined SQL
    exceeding MaxMigrationSourceBytes deny before database IO. Input is copied
    for this call; callers must not mutate the slice concurrently with entry.

    The stable native advisory lock covers discovery, execution and
    finalization. Work and lock acquisition are bounded by backend
    policy/context; independent cleanup uses a finite deadline. The pool is
    borrowed and stays open. Error formatting redacts SQL/driver diagnostics,
    but traversal may expose underlying driver causes; do not log
    unwrapped diagnostics. A commit or post-commit unlock failure returns
    ErrInstallOutcomeUnknown and no success records. Nil/canceled contexts deny
    before IO. Concurrent calls serialize through native migration ownership.
    This API does not change Runner's individual-migration transaction
    semantics.

func (backend *Backend) ReadLedger(ctx context.Context) (records []migrations.Record, err error)
    ReadLedger discovers the existing selected ledger history without preparing
    schema or acquiring the migration advisory lock. A missing ledger yields
    empty history; a non-table relation at that name returns ErrLedgerConflict.
    It never discovers or adopts another ledger name.

    Discovery uses one bounded repeatable-read, read-only transaction and the
    same row validation and resource limits as Session.Records. Returned records
    are caller-owned; dirty records remain dirty. The borrowed pool stays open.
    Error formatting is redacted; errors.Is preserves classification and error
    traversal may expose driver causes. Do not log unwrapped diagnostics.
    Concurrent calls are safe. Nil/canceled contexts deny before database IO.

    The result is a snapshot, not migration ownership or permission to apply.
    Compose BuildStatus or PlanUp with the exact source to inspect
    compatibility; execution must rediscover and validate history under acquired
    ownership. Runner.Status/Plan retain their existing locked preparation
    behavior.

type Option func(*Backend) error
    Option configures a PostgreSQL backend during construction only.

func WithLockRetryInterval(interval time.Duration) Option
    WithLockRetryInterval controls polling when another job owns the advisory
    lock. Interval must be positive; the default is 100 milliseconds. Context
    cancellation interrupts the timer between unsuccessful contention attempts.

func WithLockTimeout(timeout time.Duration) Option
    WithLockTimeout replaces the finite default advisory-lock polling timeout.
    The override must remain positive, so callers cannot disable the bound.
    Lock attempts repeat only while another session owns the lock; database
    errors are returned without retry.

func WithOperationTimeout(timeout time.Duration) Option
    WithOperationTimeout replaces the finite default deadline covering each
    complete PostgreSQL session or schema-inspection operation. The override
    must be at least one millisecond, so callers cannot disable the bound.

func WithStatementTimeout(timeout time.Duration) Option
    WithStatementTimeout replaces the finite default PostgreSQL
    statement_timeout applied to each migration transaction or explicit
    no-transaction execution session. The override must be at least one
    millisecond, so callers cannot silently select PostgreSQL's unbounded zero
    value.
